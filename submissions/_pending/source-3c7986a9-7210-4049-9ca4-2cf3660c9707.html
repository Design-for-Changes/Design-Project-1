01. 目標 🎯

大量データや複雑な情報を、分かりやすいだけでなく、面白くて触りたくなる形にしたい。現在は「3Dにすること」自体より、データの意味に合う視覚表現とインタラクションを考えることを重視している。

データを見る → 特徴を感じる → 触って比較する → 関係や変化を理解する

02. 今の本命参考資料 ⭐

今いちばん参考にしたいのは、「日本のお野菜収穫量」と「まちの計量舎」。どちらも、実データを「見れば分かる」形へ翻訳していて、派手さよりも情報と表現の対応がうまい。

日本のお野菜収穫量

infographic.jp/nippon-yasai/ ↗
01

面白いところ：都道府県ごとの収穫量を、表ではなく円の大きさ・色・位置で表現。野菜や年代を切り替えると地域差が一瞬で分かる。

収穫量→円の大きさ→地域差を直感的に理解

学び：数量を「大きさ」に翻訳し、地理と組み合わせるだけでも理解速度が大きく変わる。

まちの計量舎

keiryosha.com ↗
02

面白いところ：都市・交通・人口・行動などの実データを、地図、時系列、類似度、ミニチャートなど多様な方法で可視化。データごとに最適な見せ方を考えている。

都市データ→場所 / 時間 / 類似度→街の特徴が見える

学び：「何を比較したいか」に応じて、表現方法そのものを変える。

05. 技術候補 🧰

D3.js

独自の2D可視化、SVG、Canvas、ズーム、ネットワークなど。「データ → 見た目」の変換ルールを細かく作れる。

2DCustomInteraction

Three.js

3D空間、粒子、カメラ、光、シェーダー。データを地形・物体・世界へ変えるときに強い。

3DWebGL

deck.gl

大量の点・線・地理データをGPUで高速描画。大規模データを扱う場合の有力候補。

GPUMassive Data

GSAP / ScrollTrigger

スクロールとアニメーションを結びつける。NOËLやUnited Carriersのように「操作 = 進行」にしたいときに有効。

ScrollMotion

SVG / Canvas

WebGLを使わなくても、豊かなインタラクティブ可視化が可能。軽量で説明的な表現に向く。

2DLightweight

Plotly / Observable Plot

分析系の比較や検証用プロトタイプを素早く作る。アイデア検証の初期段階にも便利。

06. 現時点の方向性 🚀

今の興味は、単なる「3Dサイト」よりも、データの意味を保ったまま、理解しやすく面白い体験へ変換することにある。

① 全体像をまず見せる

大量データを最初から細かく読ませず、模様・色・密度・形として全体を見せる。

② 気になる場所を触る

ホバー、クリック、ドラッグ、スクロールで詳細が現れる。操作を「探索」にする。

③ データに合う比喩を使う

量→大きさ、流れ→粒子、密度→高さ、時間→動き、関係→線、階層→深度など。

④ 見たくなる世界観も大事

NOËL、RINGO、POLAのように、理解だけでなく「触りたい」「見続けたい」をつくる。

理想の探索体験

全体を眺める→気になる部分を発見→触る / ズーム / スクロール→比較・関係を見る→個別データを理解

07. 次に調べること 🔎

  • 日本語で公開されている「実データ × 面白い可視化」の事例をさらに集める
  • 参考サイトを「量・時間・流れ・関係・類似度・階層・操作」など表現タイプ別に整理する
  • 自分が扱いたい大規模データ候補を決め、そのデータに合う視覚変換を考える
  • 日本のお野菜収穫量とまちの計量舎を、本命参考としてより細かく分析する
  • 人口動態マップのような「時系列で意味が見える」表現を増やして探す
  • NOËL・RINGO・POLAのインタラクションを、データ可視化にどう組み合わせられるか考える

※ 技術名ありきではなく、「何を分かりやすくしたいか → どんな視覚変換が有効か → そのためにどの技術を使うか」の順で考える。
